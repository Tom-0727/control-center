# Paseo 公共 Skills 管理：实现方案

状态：已实现并接入控制中心，实际 Web 验收通过。产品行为以已确认的 [PRD](01-prd.md) 为准。2026-10-01 起节点分发改为一键同步，下文已按现状更新；此前的验收记录保留原貌。

## 整体实现

在 `plugins/nodes-skills-manage/` 增加 Paseo 原生插件，只安装到控制中心。插件提供界面和当前任务管理；公共技能的规则及实际文件操作集中在现有管理工具中，agent 与插件共用。

独立性为用户明确要求：全部自定义代码位于本仓库，随 Git 管理。通过官方插件 SDK、CLI 与安装配置接入，不修改 Paseo 源码、npm 安装文件或自带 Web 静态资源，不依赖对内部模块的运行时补丁，也不维护 Paseo fork。Paseo 升级时只需验证公开插件/API 兼容性，接口有变化时在本仓库适配。

```text
Paseo 页面 → 插件后端 → 公共管理入口 → 现有 Paseo 包装脚本 → 节点
                             ↑
                         agent 调用
```

| 部分 | 职责与改动 |
| --- | --- |
| 插件 `client/` | React Native 页面、状态表、技能详情、技能库更新确认、任务进度；使用 Paseo 的主题与紧凑布局接口 |
| 插件 `server/`、`shared/` | 定义校验过的 RPC 输入输出，启动管理命令，维护当前任务、进度和更新检查结果 |
| 新增 `nodes-skills-manage/scripts/controller.py` | 公共编排入口：检查/应用来源更新、盘点节点、同步到节点、校验结果；将原来依赖 agent 手工组织的步骤程序化 |
| 现有 `skills.py`、`node.py` | 复用目录、摘要、冲突、备份与远程传输；补充结构化进度，保留现有命令兼容性 |
| 现有 `paseo-nodes-use` 包装脚本 | 保留节点解析、身份检查和凭据处理；以公开终端 SDK 调用替换旧 CLI 内部模块兼容钩子 |
| 现有 skill 文档 | 指向共用入口，保留管理规则的单一来源，说明 CLI 和 GUI 的使用关系 |

插件使用独立的 package 配置，开发 SDK 固定为 `@getpaseo/plugin@0.9.2`，manifest 首版支持 `^0.9.2`。运行端由 Paseo 提供 SDK、React Native 和 Zod，不把这些库另行打包进插件。

## 来源与快照

继续读取 `.private/nodes-skills-manage/source.json`，不在插件内复制一套仓库或公共名单配置。

`source.json` 为 version 2 来源列表（2026-09-30 由单仓库加附加来源迁移而来）。每个来源是 `git` 或 `well-known`（Agent Skills discovery v0.2.0）条目，拉取逻辑在 `scripts/upstreams.py`，新增来源不需要写代码；不同来源重名时报错。插件 `add-source` / `remove-source` RPC 调用同名 controller 操作，只改来源列表并使用控制中心写锁。

检查更新时，把 Git 分支解析为实际 commit、读取发现索引条目的 sha256，获取临时候选内容，用现有发现、摘要和打包逻辑检查完整性。候选预览绑定每个技能的上游版本、候选内容摘要与控制中心原快照摘要；分支后续推进不会改变本次待确认的内容。详情提供技能和文件层面的变更，文本文件可查看内容差异。

确认应用时重新校验当前快照和候选内容。新快照写入控制中心的版本目录，完整验证后原子替换 `source.json` 的快照指向；保留原快照用于恢复。当前 `common/` 可直接作为初始版本继续使用，不要求为接入插件迁移或重新分发。

通过同一个控制中心文件锁协调快照替换和分发写任务。同步开始时冻结当前快照，各节点收到相同内容；agent 与 GUI 同时操作时，后来的冲突写请求返回忙碌状态。

## 节点编排与同步

- 节点集合从现有 `paseo-nodes-use/scripts/node.sh list` 获取，沿用节点身份校验和凭据处理。节点信息不硬编码到公开代码，凭据不进入页面返回值。
- 通过现有包装脚本列出现有工作区。唯一明确的环境工作区可自动选中；无法确定时返回候选供用户选择，并在执行前复核该工作区仍有效。插件不自动创建工作区。
- 编排入口输出机器可读结果和进度事件；agent 与插件后端都通过该入口完成多节点操作。执行命令使用固定程序和参数数组，界面不能提交任意 shell 命令。
- `sync` 一步完成，没有预览和确认。每个节点先盘点并与快照比较：已一致的直接标为校验通过，不传输；其余节点按完整公共集合执行，包含接管相同现有内容、公共撤回及链接调整。
- `skills.py` 应用时在节点文件锁内计算计划并执行。节点上有本地修改、同名未纳管内容等冲突时，该节点整次不执行并在结果中列出，不覆盖。外部程序并不遵守本工具的锁，因此执行后仍必须独立校验实际内容。
- 不可达、未选定工作区或有冲突的节点不影响其余节点；处理后对这些节点重新同步即可。
- 完成后重新盘点并核对公共集合、内容摘要和适用的链接。`applied: false` 且无差异可判为已一致；命令退出成功本身不足以标为同步成功。

现有远程分块传输先复用，节点并发上限初始设为 2。进度显示真实阶段和已传输量，不把传输百分比当成整个同步的完成比例。

已有 `terminal-send-flush.mjs` 会在单次 CLI 进程中改写内部发送模块，虽然没有修改安装文件，仍依赖内部实现。实施时在节点包装层改用公开 `@getpaseo/client` 终端 API，在同一连接中写入并等待 `capture()` 返回后再关闭；继续由原包装层处理节点身份与凭据。验证中继传输后移除旧钩子及其 `NODE_OPTIONS` 注入，运行时不引用 Paseo 的内部 `dist` 模块。

## 后台任务与页面

Paseo 0.9.2 的插件 RPC 有 30 秒超时。检查上游、远程盘点及同步都通过“启动任务 → 返回 ID → 查询状态”的短请求完成；插件后端启动管理子进程，不把数分钟的工作挂在一次 RPC 上。

后端在内存中保留有界的当前任务、最近结果及尚有效的更新检查结果。页面离开不终止任务，返回后查询当前状态；任务结束后停止高频查询，普通状态通过手动刷新更新。节点状态不依赖插件内存：controller 每次盘点、同步后写入 `nodes-status.json`（按快照标记），`overview` 返回该记录，插件重启或由 agent 执行后页面仍显示最新结论。重复提交同一更新确认返回已有任务，已有任务运行时拒绝启动新任务，控制中心和节点的锁继续防止不同入口重叠写入。

节点错误独立汇总。超时或连接断开显示结果未确认，先重新盘点，避免直接重放写操作。插件或控制中心重启后重新盘点，旧的更新检查结果失效；不承诺跨进程重启自动续跑。插件停止时清理所拥有的本地子进程和临时资源，对可能已经开始的远端操作按结果未确认处理。

页面按 PRD 的统计概览、节点与技能两个区域实现，桌面显示技能与节点状态表，紧凑布局显示节点卡片和技能列表；来源跟随每个技能展示。使用官方 `@getpaseo/plugin/client/react-native` Modal 呈现技能详情、技能库更新确认和任务结果。节点区域提供「扫描」和「同步」两个按钮，进度原位显示，主页面保留打开任务结果的入口；前端不自行重新计算管理规则。

以 `https://paseo.atectix.com` 为实际 Web 验收入口。当前站点由控制中心 daemon 提供自带 Web UI，前端已包含插件加载能力。插件安装启用后，用户连接并选择控制中心节点时，由 Paseo 动态加载插件页面和侧栏入口；无需重建或替换站点前端。插件归属控制中心，而不是浏览器所访问的域名，验收需覆盖选择正确节点和刷新/重新连接后的加载。

## 实施顺序与验证

1. **共用管理入口**：实现来源检查、固定版本候选和快照替换，接入节点发现、盘点、预览和校验。用临时 Git 仓库和隔离 HOME 验证检查无副作用、本地修改保护、更新失败后旧快照仍可用。
2. **可靠的执行边界**：以公开 SDK 终端调用替换旧兼容钩子并验证中继发送；补充预览摘要校验、控制中心锁、节点结果核对和结构化进度。保留现有测试，并验证预览后内容变化、公共撤回、专属技能保留、链接异常和部分节点失败。
3. **插件后端与界面**：实现 RPC、后台任务和页面。验证重复提交、离开后返回、无变更成功、部分成功及超时后的重新盘点；运行 TypeScript 检查和 Paseo 插件编译器。
4. **接入与实际验收**：同步更新 skill 使用说明和 README。先完成隔离验证，再在控制中心接入插件，读取真实节点状态并进行无变更的预览和同步校验；真实技能增删改使用隔离目录验证，避免为测试改变公共集合。检查实际客户端的桌面和紧凑布局。

## 接入前提与已知限制

- 控制中心当前 CLI 为 0.9.2，临时插件骨架已通过该版本编译器；部署记录中的 Web 版本同为 0.9.2，在线资源已确认包含插件加载接口。正式接入时按 manifest 再核对实际客户端版本，不为本功能自动升级 Paseo。
- 插件需要控制中心现有 Python、Node、Paseo CLI 及公开 SDK；远端继续只要求 Python 3.9+。旧兼容钩子的 Node `registerHooks` 依赖将随钩子一并移除。
- 控制中心的全局插件开关目前未配置，Paseo 按关闭处理。正式接入包含启用该开关和安装本地插件；Paseo 插件后端以 daemon 用户身份访问文件和执行进程，界面运行于 Paseo 客户端。
- 首版插件引用本仓库已有管理脚本，作为控制中心的一部分部署；不是可脱离本仓库单独分发的通用技能管理器。
- 大载荷经 Paseo 原生文件上传分段传输（每段确认，按耗时自适应），再执行一次命令；2.2 MB 快照到 Lenovo 约 44 秒，三节点分发约 45 秒。上传接口来自 SDK 的 `internal/daemon-client` 导出，升级 SDK 后需重新验证。
